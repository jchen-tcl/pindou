一个基于微信小程序的拼豆图片转换工具。

## 功能简介

- 上传相册图片
- 优先读取原图，解码失败时才尝试压缩转换，兼容常见图片格式
- 分步骤完成参数设置与结果预览

## 转换说明

- 转换时完整保留图片，居中补浅色背景；背景也计入用豆量。
- 色卡可选 MARD 221 标准版（默认）或 291 完整版；图纸、用量清单、Excel 使用 A1、H7 等 MARD 色号。291 版含特殊扩展系列，请按实际套装选择。
- RGB 采用 MIT 许可的 maxcleme/beadcolors 开源参考数据，并非厂家官方测色。来源、原始数据和许可证见 `data/mard/`。屏幕色仅供参考。
- 默认使用纯色优化，适合卡通和插画：先按目标网格的 3 倍边长采样，在稳定色块中提取主色，按 Oklab 色差合并近似色，再以区域主色决定每格颜色。
- 中性灰边缘优先归入中性色；色相约束减少蓝色、粉色互相污染；对穿过格子的细黑线保留较低的覆盖率门槛，保护轮廓。
- 颜色数量是上限，不强行凑足色号。提取主色后使用 Oklab 匹配 MARD 色卡，最后清理低色差的 1～2 格孤立杂色。默认不再提亮原色，不添加抖动。
- 色卡限色仍比较贪心与按用量选色方案的总 Oklab 平方误差。合并色块会主动舍弃细微渐变，因此整体流程不以最小原图像素误差为目标。
- 照片、细腻渐变和极小图案可能丢失层次；32×32 的格数也不足以还原所有五官。建议细线图用 64×64 或 128×128。内部 `restore` 模式保留原来的逐像素配色，历史 `cute` 调用仍兼容。
- 相同像素通过直方图合并，色差预计算后复用；未添加抖动。
- 成品尺寸随网格变化，按 5 mm 间距估算；实际尺寸取决于所用豆粒和底板。
- Excel 导出覆盖应用内的 `effect_current.xlsx`，需要保留的版本请通过预览菜单另存。

## 回归测试

安装 Node.js 后运行 `node --test tests/*.test.js`。
测试使用模拟微信接口，覆盖配色、完整保留图片、压缩回退和统计一致性。
纯色测试另外覆盖近色噪点、中性边缘、稀有彩色细节、眼睛高光、细黑线及所有网格的色数上限。
Canvas 显示、相册授权及 Excel 预览仍需使用微信开发者工具和真机验证。

安装 Pillow 后，可用 `python scripts/compare-image.py 输入图片 输出目录` 生成四种网格的算法前后对比和色号统计（需要 Node.js 在 PATH）。该工具用 Pillow 近似缩图采样，不等同于微信 Canvas 真机结果，不修改原图。

算法参考方向：[Pixelated Image Abstraction](https://www.cs.columbia.edu/cg/pdfs/197-pixelated_image_abstraction.pdf)、[Content-Aware Downsampling 的卡通对比](https://johanneskopf.de/publications/downscaling/supplementary/pixel_art/index.html)。本项目是无第三方运行时依赖的轻量启发式实现，并非上述论文算法的完整复现。
